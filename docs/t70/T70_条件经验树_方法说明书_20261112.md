## 1. 项目定位和要解决的问题

### 1.1 任务与目标

T70 是建立在 EDGE 经验检索与更新机制之上的多轮 Search QA 强化学习实验。训练学生模型是 Qwen2.5-3B-Instruct 的 LoRA 策略模型；环境为最多四次工具交互的 Search QA，最终奖励为二值正确性。部署和验证的目标均为**不注入外部经验**时的学生策略表现。

核心研究问题不是“经验检索能否让一次回答更容易正确”，而是：**利用经验树在困难问题上发现的成功行为，能否通过 GRPO 和弱辅助监督转化为学生模型自己的无经验行为能力？**

本方案针对三个具体困难：① 直接 RLVR 容易因答案奖励稀疏而没有有效对比；② 对所有问题都运行经验树会产生不必要的计算，并让简单问题的监督结构变复杂；③ 经验辅助轨迹的上下文与无经验自主执行的上下文并不完全一致，需要谨慎选择内部化监督的来源和强度。

### 1.2 核心设计原则

1. **自然探索优先**：先观察模型自己能否解决问题，不让经验树替代常规策略探索。
2. **只在困难题介入**：以四次自然采样的成功数判断是否运行完整经验树，而不是人为切换训练阶段。
3. **GRPO 是主目标**：自然轨迹和树轨迹参与同一个问题组的强化学习目标，不分裂成两个互相竞争的优化器。
4. **蒸馏是弱辅助**：OPSD=0.1、成功 SFT=0.05；不能把这两个系数直接解释为实际梯度占比。
5. **分叉有严格来源**：Utility、Reflector 和 OPSD 使用实际树上的同状态 L/R 分叉，不用自然成功/失败样本伪装经验干预。
6. **代码等价和实验可追溯**：共享节点去重保留所有叶子贡献，完整树快照、经验库状态与运行配置用于审计。

## 2. 整体框架

```text
训练题目 q
  │
  ├─ 无经验独立自然采样 ×4（完整多轮 Search 轨迹）
  │       └─ 获得自然成功数 k(q)∈{0,1,2,3,4}
  │
  ├─ k(q)≥2：不生成经验树
  └─ k(q)≤1：运行完整 T/S 条件经验树
          ├─ T：根节点的任务级经验对照
          ├─ S：后续节点的当前状态级经验对照
          ├─ L：当前分叉不新注入经验
          └─ R：当前分叉新注入检索到的经验
               └─ 产生真实 L/R Fork 的终局叶子集合
  │
  ├─ 按题目 UID 汇总自然叶子 + 树叶子
  ├─ 统一问题组 GRPO（共享 Node 去重、精确保留正负优势）
  ├─ 合格真实 Fork → OPSD（系数 0.1）
  ├─ 成功轨迹 → 无经验 Student SFT（系数 0.05）
  │
  └─ Actor 参数更新

并行于优化的经验生命周期：
真实 Fork → 问题级 Utility 证据 → 每5步 EMA → Reflector 40→10→0–5
          → 新经验入库 / UCB 检索 / 暴露统计 / 负收益删除 / 持久化
```

**注意**：此图表示算法阶段的逻辑关系，并不表示自然采样与经验树是 GPU 并行执行的。T70 先运行自然采样，再对满足条件的问题运行树。

## 3. 条件触发：四条独立自然轨迹

给定训练问题 `q` 和当前策略 `πθ`，先在**不检索、不注入 T/S 经验**的情况下独立产生四条完整轨迹：

`τ¹_N, τ²_N, τ³_N, τ⁴_N ~ πθ(·|q, no-experience)`。

每条轨迹执行实际 SearchEnv，最多四轮行动，单独得到终局奖励 `r_i∈{0,1}`。定义 `k(q)=Σ_{i=1}^4 r_i`，则条件触发函数为：

`z(q)=𝟙[k(q)≤1]`。

- `k=0` 或 `k=1`：对问题运行完整经验树，并保留四条自然轨迹。
- `k=2,3,4`：不运行经验树，仅由四条自然轨迹进入训练批次。

这里“独立”是四次独立采样与环境执行、独立 Node/Leaf ID，而不是要求四次生成的 Token 必须不同。训练时只**监控**完全相同的 Prompt/Response/Mask 序列比例，不合并自然轨迹或丢弃相应奖励。

设计动机：为当前模型已经有一定自主成功率的问题保留简洁的自然 RLVR 信号，将昂贵的树对照集中到模型尚难成功的问题。`k≤1` 是本次实验固定的超参数，不声明其理论最优。

## 4. T/S 经验树及同状态分叉

### 4.1 树的结构

经验树只在被触发的问题上执行。状态包括原始问题、检索与观察历史、当前轮次、任务级经验记忆、父节点与路径标识等。每个状态执行一次检索：

- **根节点（T，task-level）**：根据原始问题检索任务级经验（运行配置 `task_top_k=4`），针对全局解题策略建立 L/R 对照。
- **后续节点（S，step-level）**：根据“原始问题 + 当前 Observation”检索状态级经验（`step_top_k=6`），针对下一步行动建立 L/R 对照。

如果某状态检索不到可注入的新经验，则只扩展 L 分支，不生成虚假的 Fork。

### 4.2 L/R 的真正含义

对于检索到经验 `E(s)` 的共同分叉前状态 `s`：

- **L 分支**：在当前动作中**不新注入** `E(s)`。
- **R 分支**：在当前动作中**新注入** `E(s)`。

两边共享分叉前状态，但其后各自生成行动、执行工具和继续发展成子树。**L 不必然意味着整条历史从未使用经验**：较深的 L 分支可能继承祖先 T 经验已影响的历史；因此“本次局部不注入”与“完全自主无经验”必须严格区分。

树的同状态对照可以降低决策状态混杂，但两侧仍存在随机采样、不同下游检索等混杂；不能将子树奖励差直接宣称为已识别的严格因果效应。

### 4.3 叶子与奖励

一个叶子对应一条从根到终局的行动路径，成功奖励 `r(τ)∈{0,1}`；Node 可被多条叶子共享。树按真实环境四轮行动预算终止；越界和不合法终局将导致校验失败，而不是隐式截断为虚拟成功。

## 5. 统一 GRPO：自然叶子和树叶子在一个问题组训练

对每道题，令 `L_q = L_q^N ∪ L_q^T`：四条自然叶子集合 `L_q^N` 永远存在；只有 `z(q)=1` 时才存在树叶子集合 `L_q^T`。

代码对该问题全部叶子的训练分数做组内归一化：

`y_τ = r(τ) - λ_invalid × N_invalid(τ)`，

`A_τ = (y_τ - mean_{η∈L_q} y_η) / (std_sample({y_η}) + ε)`，若样本标准差为 0 则 `A_τ=0`。

实现中 `λ_invalid` 来自有效动作惩罚配置，运行值为 `0.01`。注意该惩罚只影响训练 Advantage 的分数，不等同于 Utility 使用的二值终局奖励。

随后，对每条叶子路径上的所有行动 Token 计算基于旧/新策略概率比的裁剪策略损失。共享 Node 不能简单只保留一条叶子，因为同一节点可能属于优势不同的路径。

### 5.1 共享前缀精确去重

对唯一 Node `v`，把它在所有叶子中的正负 Advantage 贡献分别聚合：

`A⁺_v = Σ_{τ∋v} max(A_τ,0)`，`A⁻_v = Σ_{τ∋v} min(A_τ,0)`，`m_v = |{τ:v∈τ}|`。

Actor 对 Node 只进行一次主要前向，再按 `A⁺_v`、`A⁻_v` 与 `m_v` 重建原展开叶子的裁剪损失；SFT 成功路径的重复权重、KD canonical 行与 Padding 也分别保留。T70 进一步采用**先选唯一节点、再打包大张量**，而不是完整展开后才构造去重数据。

这属于数值等价的工程优化；不能把去重后的 Node 数量误称为独立采样次数。

### 5.2 为什么不纠正困难题的额外训练权重

树触发题有四条自然叶子外加更多树叶子，因而在 Token 级损失中可能占更大权重。这是当前明确保留的训练设计，反映将计算与学习信号集中于困难题；它不是“每题完全相等”的 Objective。论文必须如实描述，后续可作为消融方向，不能暗中宣称按题等权。

## 6. OPSD：有正向子树差异才进行弱辅助蒸馏

**本节是本次方案与早期 T069 门控不同、最容易遗漏的关键修订。**

### 6.1 触发门控

对真实 Fork `f`，左、右子树的终局叶子奖励分别为 `R_L(f)` 和 `R_R(f)`。定义：

`p_L(f) = (1/n_L) Σ_{τ∈L_f} r(τ)`，

`p_R(f) = (1/n_R) Σ_{τ∈R_f} r(τ)`，

`Δ_f = p_R(f) - p_L(f)`。

当前 T70 只在以下三个条件**同时满足**时触发 OPSD：

`g_f = 𝟙[本轮 R 真正注入了新经验] × 𝟙[normalize(a_L) ≠ normalize(a_R)] × 𝟙[Δ_f > 0]`。

**不再要求**“左子树全部失败、右子树至少一条成功”；例如左侧 25% 成功、右侧 75% 成功也可蒸馏。**不要求**经验历史 Utility≥0，也**不对**存在祖先 T 的路径再乘额外 `0.5`。

动作比较使用规范化的 Search/Answer 动作文本；并非只比较模型完整原始输出字符串。以上三个条件仅控制蒸馏监督，不修改 Utility 的统计口径。

### 6.2 分叉权重：正向差异 × 右侧小样本收缩

`w_f = g_f × (p_R(f)-p_L(f)) × n_R/(n_R+1)`。

示例：`p_L=0.25`、`p_R=0.75`、`n_R=4`，得到 `w_f=0.5×4/5=0.4`。这种权重同时关注右侧相对收益与右侧样本数，避免小样本右侧单次成功直接获得满权重。

该式**不是**旧版 `成功右叶数/(右叶总数+1)`，也不是额外把祖先 T 的权重减半。

### 6.3 Teacher、Student 与损失

- **Teacher**：真实 Fork 的 R 节点，看到本次注入的经验，生成概率分布；只对被激活的 KD 行计算 Teacher Forward。
- **Student**：同状态下不带当前注入经验的策略预测；对于已含祖先 T 的路径，额外计算明确的无经验 Student Prompt，避免简单复用受经验影响的主前向。
- **Token 支持集**：Teacher Top-k=20，计算支持集内的 Reverse KL 形式。实现中 Teacher 分布 `detach`，Student 接收梯度。

记当前 Fork 选中 Token 上的蒸馏损失为 `D_f`，则可概括为：

`L_OPSD = (Σ_f w_f Σ_{t∈f} D_f(t)) / (GRPO 实际展开 Token 总数)`。

实际代码采用当前 GRPO micro-batch 的 Token 分母，并执行四 GPU Replica 归一化。**全局损失系数 `λ_OPSD=0.1`**，所以优化中的贡献是 `0.1 × L_OPSD`，而不是“OPSD 梯度恒为 GRPO 的 10%”。

## 7. 成功轨迹无经验 SFT

对所有终局奖励为 1 的自然/树叶子，其沿途行动的有效响应 Token 都可产生成功模仿信号。Student 使用对应状态的**无 T/S 注入 Prompt**，监督目标仍是该成功路径实际生成的动作 Response。

`L_SFT = - [Σ_v s_v Σ_t log πθ(a_{v,t}|h_v,no-exp)] / [Σ_v s_v × valid_tokens(v)]`，

其中 `s_v` 是共享节点被成功叶子引用的次数。主前向本来就是无经验 Prompt 时会复用该 Log Probability；只有 Prompt 确实不同才额外进行 Student Forward。

全局系数 `λ_SFT=0.05`。它与 OPSD 的 KL 强度和归一化方式不同，不宜通过“0.05 小于 0.1”直接比较梯度大小。

**重要边界**：树成功路径虽然在当前训练 Token 上移除了经验文本，但该路径前序历史仍可能是由经验引导产生的。这意味着 SFT 是“对成功动作的无经验条件化训练”，不等价于完全消除了行为历史分布差异。

## 8. 联合优化目标

T70 的主损失可以概括为：

**`L_total = L_GRPO + 0.1 × L_OPSD + 0.05 × L_SFT`**。

此外，Actor 内部依配置保留原来的有效动作惩罚在 Advantage 分数中的作用，并使用标准 PPO/GRPO 的裁剪策略目标。当前训练配置没有额外的 Actor KL Loss（`use_kl_loss=False`），熵损失系数为 0。

这表达的是各目标的加权组合，不意味着三项损失在梯度空间中相互正交，也不意味着蒸馏强度能直接由系数估计。具体 PG/KD/SFT 梯度范数和方向需由实际训练诊断验证。

## 9. 经验检索与动态生命周期

### 9.1 检索

经验分为 `task_experiences`（可复用的整体解题策略）和 `step_experiences`（具体状态/动作决策规则）。根节点通过原始问题进行任务级检索；非根节点使用原始问题和最新 Observation 进行步骤级检索。

当前检索排序基于相似度、Utility 和 UCB 探索项。对候选经验 `e`：

`score(e) = α × sim_norm(q,e) + (1−α) × [U_e + c √(log(1+N)/(1+n_e))]`。

代码默认 `α=0.5`、`c=0.5`。`n_e` 是真实注入暴露次数，`N` 是经验池总暴露量。只有实际 Fork 的 R 节点新注入该经验才累加暴露；自然采样与仅被检索但未注入的情况不构成树方法所统计的曝光。

### 9.2 Utility：按问题去重的经验增益估计

对于同状态 Fork，若 L/R 当前动作规范化后相同，**不记 Utility**；若不同，则记录 `Δ_f=p_R−p_L`，无论它正、负还是恰为 0。零收益且不同动作的真实对照不能被随意过滤，否则会系统性偏移经验价值估计。

同一个“经验 ID × 原始问题”键下的多个 Fork 先取平均，避免深树的一道题重复计票；累积为五步管理窗口内的不同问题观测。

每五个外层训练 Step 更新一次 EMA：

`U_e ← (1−β) U_e + β × mean_window_question_gain(e)`，其中 **`β=0.1`**。

若某经验该管理窗口没有被有效观测，不将其当作负收益；连续负收益窗口计数也不会跨过未观测窗口累加。历史总体统计可保存用于分析，但不再直接充当经验删除条件。

### 9.3 动态删除

经验**硬负收益删除**同时要求四个条件：

1. 当前训练步距创建步至少 **20 Step**；
2. 真实累计注入暴露次数至少 **5**；
3. 当前 Utility **≤ −0.1**；
4. 至少 **2 个连续的负收益管理窗口**。

这四项是 AND 关系，并非其中任一项即可删除。另有独立的**容量删除**：任务级/步骤级经验池各最多 200 条，超出上限时按保留得分优先清理低分且不在保护期内的条目。负收益删除与容量删除不能混同。

已删除经验 ID 不应复用。经验库实现使用持久化 ID 高水位、历史 ID 预留和去重指纹来防止重启或删除后 ID 冲突。每 10 Step 的训练 checkpoint 对应保存可恢复的树证据与经验库状态。

## 10. Reflector：只从真实树分叉生成经验

### 10.1 候选严格来源

**自然四条轨迹不能进入 Reflector 候选池。** 候选只来自真实 T/S 树中相同分叉前状态、左右当前动作有实质差异，且具有可配对成功/失败完整路径的 Fork。左右子树成功率可以正向或负向不同；Reflector 用两者的对比发现错误决策，不要求候选一定说明“经验帮助成功”。

候选排序优先有明显成功/失败差异的分叉、不同搜索计划、可诊断的具体状态错误，并对仅改写搜索查询或随意猜答案的样本降权。相较下游存在其他经验干预的路径，优先选更少混杂的轨迹配对。

### 10.2 40 → 10 → 0–5

- **候选构造**：在当前管理 Step 的实际树上，最多取得 40 个真实 Fork 案例；不足 40 个不以自然对照补足。
- **模型选择**：API 从候选中选最多 10 个高质量、互补的对照；候选数 ≤10 时可不调用选择模型，选择异常时使用确定性回退。
- **经验写入**：向 Reflector 提供选中的完整轨迹和已有经验库信息，输出 **0–5 条**新经验；允许完全不生成新经验。

`task` 和 `step` 是经验适用性的类别，而不是单凭分叉深度强制划分。根分叉更容易提供任务级规划线索，内部节点更容易产生具体状态级规则，但仍需根据文本内容及证据判断。新经验经过格式校验、重复内容指纹过滤和 ID 分配，再加入库中，并在下一个检索周期发挥作用。

**谨慎表述**：成功/失败路径的差异是经验候选的诊断证据，不构成充分因果识别；本方法通过监督的保守门控、优先少混杂的候选和后续 Utility 动态评价，尽量降低错误经验的影响。

## 16. 可直接改写为论文 Method 的表述（中文稿）

**条件触发的经验树探索。** 对于每个训练问题，我们首先从当前策略独立采样四条不依赖外部经验的完整交互轨迹，并根据其二值终局奖励估计问题的当前求解难度。仅当成功轨迹数不超过一条时，我们对该问题执行经验树探索。经验树通过对同一决策状态分别构造不注入与注入检索经验的 L/R 分支，继续向后执行搜索交互，从而获得包含不同决策过程及终局结果的结构化轨迹集合。根状态检索任务级规划经验，后续状态根据原问题与当前观察检索步骤级决策经验；自然轨迹本身始终独立于经验检索。

**统一的强化学习优化。** 我们将同一问题的自然采样轨迹与经验树叶子合并为一个 GRPO 组，根据终局奖励及有效动作惩罚计算组内标准化优势。由于多条叶子可能共享早期树节点，我们按节点聚合来自各叶子的正负优势，进行数值等价的共享前缀去重，以免重复执行相同的策略前向。这使模型的主训练信号仍来自同题轨迹的相对收益，而不是将经验文本本身作为模型部署所必需的条件。

**子树收益感知的弱蒸馏。** 对任一真正注入新经验的树分叉，设左右子树成功率分别为 `p_L` 和 `p_R`。只有在左右当前动作不同且 `p_R>p_L` 时，我们才以右侧经验条件化策略作为 Teacher，向不携带该次经验的 Student 施加蒸馏损失。蒸馏权重设置为 `(p_R-p_L)·n_R/(n_R+1)`，以反映成功率增益并抑制右子树样本过少造成的不稳定监督；Teacher Top-k 分布上的 Reverse KL 作为辅助目标，整体系数为 0.1。此外，我们对成功轨迹使用系数 0.05 的无经验条件化 SFT，以巩固已发现的有效行动。两项辅助监督均不替代 GRPO 主目标。

**经验库的闭环更新。** 我们仅使用真实同状态树分叉评估已有经验的效用，忽略未改变当前动作的对照，但保留不同动作下的零收益和负收益观测。每条经验在同一问题上的多个对照先合并，再以五步窗口和 `β=0.1` 的 EMA 更新 Utility。Reflector 从真实树分叉中构造最多 40 个有效成功/失败案例，经选择器保留最多 10 个，再生成 0–5 条任务级或步骤级经验。经验库结合检索相似度、近期 Utility 与 UCB 探索项进行选择，并对长期负收益且充分暴露的经验施加保护期、暴露次数与连续负窗口的联合删除约束。整个训练过程不需要在推理时继续向学生注入经验。

---

**方法定位（一句话）：** T70 是一种“先独立探索、仅在困难题运行经验树、统一强化学习、用正向子树差异做弱蒸馏并持续维护经验库”的多轮 Search QA 训练方法；其目标是在不依赖经验检索的部署条件下提升学生策略，而不是把外部经验作为推理时的永久插件。**
